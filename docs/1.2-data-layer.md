Design choices worth noting:

- **Injectable fetch, not global patching.** `PostgrestClient` takes `fetchImpl?` — tests
  construct a client whose fetch records each request (`method`, URL, headers, body) and
  answers from a route table. No `vi.stubGlobal` magic, and the assertion surface is the
  real wire shape.
- **`vnd.pgrst.object+json` for single-row reads/writes.** `selectMaybeOne` / `update` /
  `deleteOne` send the object accept header and map `406 + PGRST116` — and, defensively, a
  `200 + []` body — to `null`. Callers turn `null` into the explicit not-found message (§9);
  the data layer never phrases it as "no records".
- **`or=` filter built as `in.(…)` / `eq.…` / `ilike.*…*` raw pairs**, URL-encoded by
  `URLSearchParams` — the same encoding supabase-js produces. The `*` wildcard is
  PostgREST's URL-safe equivalent of `%`; Voc's `%…%` inside `or=` is semantically
  identical.
- **Tag-diff update returns the PATCH row, not fresh tags** — mirrors Voc's `updateRecord`
  (the detail page refetches; here `get_record` refetches).
- **No client construction from `Env` yet** — that wiring needs `authInfo` (Task 3/5), so
  it is deliberately left to the task that has the credential in hand.

## Issues hit and how they were resolved

### 1. A `*/` inside a doc comment terminated the comment early

First `tsc` run: `error TS1160: Unterminated template literal` at the end of
`postgrest.ts` (line 229, past the last line of code). The doc comment

```ts
/** `content-range: 0-19/42` → 42; `*/0` → 0; missing or `*` → null. */
```

contains the sequence `*/` inside `` `*/0` ``, which closed the block comment mid-line; the
remainder was parsed as (backtick) code. Resolution: rephrase the comment so it never
contains `*/`. Lesson: don't put the `a/b` fraction form or `*/` inside JSDoc.

### 2. `z.uuid()` rejects RFC-invalid test UUIDs

The Zod boundary test for `source: null` failed — but not because of null. Zod 4's
`z.uuid()` enforces RFC 4122 version + variant nibbles: the fourth group must start with
`8/9/a/b`. The test constant `2222…-2222` (fourth group `2222`) is not a valid UUID.
Reproduced with a two-line node probe against the installed zod 4.6.5, then switched the
schema tests to a version-4 UUID (`…4222-8222…`). Row-id constants in the PostgREST stub
tests are unaffected — PostgREST doesn't validate UUID v4 bit layout.

### 3. Voc's `,()` sanitize produces multiple spaces — keep it, don't "fix" it

`'commute,(daily)'` → `'commute  daily'` (two spaces): Voc's `sanitizeSearchTerm` replaces
each stripped char with a space and trims, without collapsing runs. The first test expected
a single space and failed. Since §5.3 mandates mirroring Voc exactly (and PostgREST's
`ilike` treats the spaces literally either way), the implementation keeps Voc's behavior
and the test now asserts it explicitly.

### 4. Rollback tests initially had incomplete stub routes

The create-rollback tests failed because the stub threw on the rollback's
`DELETE /rest/v1/records` — the route table only answered `POST`. Added the DELETE branch
to both stubs (and the empty-union search test now asserts `/records` is *never* hit when
the union is empty).

## Verification (exit criteria evidence)

| Criterion | Command | Result |
|---|---|---|
| Types clean | `pnpm typecheck` (`tsc --noEmit`, TS 7.0.2) | exit 0, no output |
| All unit tests green, offline | `pnpm test` (Workers pool, stubbed fetch) | **34 passed** — records 15, search 10, tags 8, smoke 1 |

Key assertions proven by the suite:

- create = `POST records` (with `user_id`, full field set) → `POST record_tags` (rows) →
  `POST review_states` with body exactly `{ record_id }`; step-2/step-3 failure triggers
  `DELETE records?id=eq.<id>` and an error naming the step + "nothing was saved"; failed
  rollback is reported ("may still exist").
- search builds `or=(content.ilike.*…*,meaning.ilike.*…*)` from the sanitized term; tag
  filter = `GET record_tags?tag_id=in.(…)` then `id=in.(deduped ids)`, embed stays
  `record_tags(tags(*))` with no `!inner`; `count=exact` + `content-range` →
  `{ records, total, hasMore, page }`; order specs `created_at.desc,id` /
  `created_at.asc,id` / `content,id`.
- update = `PATCH` full `{type, content, meaning, source, notes}` → tag read → delete only
  removed ids → insert only added ids; zero-row PATCH (`PGRST116`) → `null`, tags untouched.
- delete = `DELETE records?id=eq.<id>` with `Prefer: return=representation`, returns the
  deleted row.
- Every request carries `apikey` + `Authorization: Bearer`.
- Zod: content 501 / meaning 2001 / source 501 / notes 4001 rejected; explicit `null`
  clears on update; bad type / blank trimmed content rejected.
